# Contributing to React-Native-Starterpack

React-Native-Starterpack is an open, community-driven collection of reusable React Native components, code examples, guides, and complete application recipes.

The idea is simple: **if you build something that might help you or someone else in the future, share it!**

## What Can You Contribute?

Anything you think would be useful, including:

- **UI components** — buttons, cards, inputs, modals, and other reusable elements.
- **Animations** — transitions, loading indicators, effects, and interactive animations.
- **Guides** — setup instructions, explanations, and practical walkthroughs.
- **Recipes** — complete, functional applications that demonstrate how different features work together.
- **Improvements** — bug fixes, better implementations, and useful additions to existing contributions.

If you have an idea that could save someone time or help them solve a problem, it is worth considering.

## How to Contribute

1. Fork the repository.
2. Create your component, guide, recipe, or improvement.
3. Place it in the appropriate folder.
4. Include a `README.md` explaining what it does, how to use it, and any required dependencies.
5. Test your code and make sure it works.
6. Submit a pull request describing what you added and how it can be used.

Contributions do not need to be large or complicated. Even a small, well-documented example can be valuable.

## Where Should Things Go?

The repository is organized into three main sections:

- **`components/`** — reusable UI components and other building blocks that can be added to existing projects.
- **`guides/`** — setup instructions, tutorials, explanations, and focused examples showing how to implement specific functionality.
- **`recipes/`** — complete, functional applications that users can build by following the provided instructions.

If an appropriate category does not exist, feel free to create a new base folder that fits your contribution. The existing structure is intended to grow with the community.

Whenever possible, give each component, guide, or recipe its own folder with its own README and relevant source code.

## Dependencies and Packages

**Please do not include full `node_modules` folders or bundled npm packages in your contributions.**

Instead, document the required dependencies and their installation commands in the relevant `README.md`. Contributors should provide the source code, configuration files, and instructions necessary to reproduce the result, allowing users to install only what they need.

For example:

```bash
npx expo install react-native-maps
```

Only include dependencies that are actually required, and explain any additional configuration needed to make the example work.

## Working on Existing Contributions

Please respect other contributors' work and avoid rewriting or replacing existing contributions unnecessarily.

If you find a bug or see an opportunity to improve an existing example, you are welcome to submit a pull request. Explain what you changed and why the change is useful.

Keep improvements focused, and test your changes to ensure they work as intended.

## Pull Request Reviews

**Currently, I am the only person reviewing and accepting pull requests.**

I will do my best to review contributions as soon as possible, but I may not always be available. If your pull request remains open for a while, it does not necessarily mean there is a problem with your contribution; I may simply be unavailable to review it at that time.

Thank you for your patience and for taking the time to contribute. Your contributions are appreciated, even if the review process occasionally takes longer than expected.

## A Few Guidelines

- Keep your code readable and easy to understand.
- Avoid unnecessary dependencies.
- Include clear documentation and usage examples.
- Test your changes before submitting a pull request.
- Never commit passwords, API keys, private credentials, or other secrets.
- Be respectful of other contributors and their work.
- Keep examples focused, practical, and easy to reuse.

## Final Note

This project is meant to grow through shared experience and practical solutions.

You do not need to be an expert or build something groundbreaking. If something helped you, it might help someone else too.

**Build it. Share it. Help someone else build something better.**
