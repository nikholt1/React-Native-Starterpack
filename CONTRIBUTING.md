# Contributing to React-Native-Starterpack

React-Native-Starterpack is an open collection of reusable React Native components, animations, code examples, guides, and recipes.

The idea is simple: **if you build something that might help you or someone else in the future, share it!**

## What Can You Contribute?

Anything you think would be useful, including:

- **UI components** — buttons, cards, inputs, modals, and other reusable elements.
- **Animations** — transitions, loading indicators, effects, and interactive animations.
- **Guides** — setup instructions, explanations, and practical walkthroughs.
- **Recipes** — complete solutions for common tasks, such as Firebase integrations, maps, navigation, and data management.
- **Improvements** — bug fixes, better implementations, and useful additions to existing features.

If you have an idea that could save someone time or help them solve a problem, it is worth considering.

## How to Contribute

1. Fork the repository.
2. Create your component, animation, guide, recipe, or improvement.
3. Put it in the appropriate folder.
4. Test your code and make sure it works.
5. Submit a pull request explaining what you added and how it can be used.

That's it! Contributions do not need to be large or complicated.

## Where Should Things Go?

Please keep the existing project structure organized:

- `packages/ui/` — reusable components and animations intended for the npm package.
- `guides/` — setup instructions, tutorials, and explanations.
- `recipes/` — practical, reusable solutions for specific tasks.
- `examples/` — complete examples or demonstrations of functionality.

Whenever possible, add new guides and recipes as separate files in their respective folders instead of modifying unrelated contributions.

**Important:** The `packages/ui/` folder should remain functional. Changes to the package should not break existing components, exports, or the build process.

## Working on Existing Contributions

Please focus on your own ideas and additions rather than rewriting or replacing other people's contributions.

If you find a bug in an existing contribution, you are welcome to fix it and submit a pull request. Improvements are encouraged when they solve a real problem, but avoid unnecessary changes to someone else's work.

## A Few Guidelines

- Keep your code readable and easy to understand.
- Avoid adding dependencies unless they provide clear value.
- Include a short explanation and usage example for new components or recipes.
- Test your changes before submitting a pull request.
- Never commit passwords, API keys, private credentials, or other secrets.
- Be respectful of other contributors and their work.

## Final Note

This project is meant to grow through shared experience and practical solutions.

You do not need to be an expert or build something groundbreaking. If something helped you, it might help someone else too.

**Build it. Share it. Help someone else build something better.**
